# Open work

What is still missing or worth doing next. Everything else in this file's history is done.

- **Extras catalog in the Windows GUI.** The catalog (`spec/extras.json`) is available on Windows through the CLI (`/extras:`, `/list-extras`) and in the Linux installer interactively; a picker in the GUI is the remaining piece.
- **Telemetry settings in the GUI.** Consent is asked on first start and stored in `preferences.json`; an Advanced checkbox to change it later would avoid editing the file by hand.
- **Refresh drives** button and a **Cancel** button during install (see `FEATURES.md`).
- **Catalog entry type for single files.** Today an entry is an ISO (optionally inside a zip) or a manual pointer. A `file` type with the same download-and-checksum path would carry tool binaries and other bootable payloads into `Extras/<category>/`: WinPmem for memory acquisition on a running Windows machine (`go-winpmem_amd64_1.0-rc2_signed.exe`, GitHub publishes its SHA-256), the EDK2 UEFI Shell (`shellx64.efi` from pbatard/UEFI-Shell, Ventoy boots `.efi` files) for firmware and Secure Boot work. Needs the validator in `tools/gen_spec.py`, the Linux `installExtras` and `extras.cpp`; the ISO path already does everything but the naming.
- **Windows triage tools.** FTK Imager, KAPE, Magnet RAM Capture, DumpIt and Arsenal Image Mounter sit behind registration or license agreements, Eric Zimmerman's tools have no stable hashes, and WinFE is built by hand from the Windows ADK. At most `manual` entries with instructions; none can be downloaded and verified by the installer.
- **Kali Linux live (forensic mode).** `cdimage.kali.org`, `kali.download` and the mirrors answer 404 to direct ISO URLs even for the versioned paths; only the torrent works. Adding it needs a torrent download path for extras.
- **Failing-drive cloning.** OpenSuperClone (the successor of HDDSuperClone) ships only `.deb`/`.rpm` on GitHub; add it when a live ISO with published checksums exists. Until then SystemRescue's ddrescue is the answer.
- **Ventoy plugin configuration for extras.** Write or merge `ventoy/ventoy.json` on the stick with `auto_memdisk` for the FreeDOS image (removes the manual F1 step) and `menu_alias` entries with readable names for the catalog images. MediCat ships its own `ventoy.json`, so this must merge, not replace.
- **`--extras recommended`.** A named preset for the repair kit (SystemRescue, Super Grub2 Disk, GParted Live, Clonezilla, Memtest86+, ShredOS, Hiren's BootCD PE) in both CLIs, so a 64 GB stick gets the useful set without picking ids.
- **Headless install smoke test.** CI exercises the information commands, `/extras` and `/verify` on a throw-away VHD (`tests/windows/smoke_cli.ps1`); a full `/install /yes /quiet` run needs the 23 GB archive and is still manual.
